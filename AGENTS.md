
- Public-page SEO (social cards, Organization/WebSite schema, en-GB locale) comes from src/lib/seo.ts; responsive photo variants from src/lib/images.ts — keeps metadata and image sizing consistent across routes.
- Single market (UK, GBP): pricing lives in PLAN_PRICING in src/lib/config.ts; retired price ids map via LEGACY_PRICE_PLAN in config.server.ts — old subscriber rows must keep resolving to a plan.
- Listing packs are two parallel Claude tool-use calls (core + marketing) run by src/lib/generation.server.ts (prompts in src/lib/prompts/); only core success consumes a credit, so a marketing failure never costs the agent their listing.
- The generator form renders from FIELD_DEFS in src/lib/listing-fields.ts (labels, dictation mode, extraction eligibility); add new fields there so they get a mic and "Fill the form" support automatically.
- Material Information, room-size conversion and the fact check are deterministic (src/lib/material-info.ts, measurements.ts, fact-check.ts) — never AI — so compliance guidance and imperial figures are predictable and unit-tested.
- After touching src/lib/prompts/*, master-listing-prompt.ts, voices.ts, listing-fields.ts, material-info.ts or fact-check.ts, run `bun run prompts:export` then `bun run test` — docs/workbench/ must mirror exactly what the app sends; refresh golden fixtures with `bun run prompts:golden` only for intentional prompt changes. Compare prompt versions with `bun run evals` (`--regrade <dir>` re-scores a saved run without API calls).
- Planning/building-regs caveats on key features are applied deterministically by src/lib/feature-caveats.ts (via labelCore), with a matching eval grader, so supplied approval caveats never depend on the model remembering them.
